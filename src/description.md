Run bash commands as tasks: Git Bash on Windows, system bash elsewhere. Write POSIX bash.
- start: runs `command` in a fresh bash and waits up to waitMs (default 30000). If it exits in time you get the final result; otherwise a taskId and the output so far while it keeps running. A non-zero exit code is a normal result. Every start is a new shell: cd and exports do not carry over, so pass cwd (default: the working directory the session started in) or chain with &&. NUL bytes in command are rejected before execution.
- poll: resizes the terminal (PTY only) with cols and/or rows, then writes `input` exactly as given, then presses `keys` (PTY only), closes stdin when eof is true, waits until the task ends, a returnWhen condition holds, or waitMs elapses (default 2000 with a resize, input, or keys and no returnWhen, 30000 otherwise), and returns only output you have not seen. Use long waits (up to 240000, which returns within a 5-minute prompt-cache lifetime; poll again to wait longer) for builds and tests, and returnWhen for servers, prompts, and TUIs; avoid repeated waitMs 0 polls and sleep commands. The process keeps running past every wait.
- kill: ends the task's whole process tree; poll afterwards for remaining output. Processes a command leaves running belong to its tree and end when its root bash exits, and the result names them: those started with `&`, `nohup`, `setsid`, `start`, or `Start-Process`, and servers a CLI starts for itself, such as the adb server or a Gradle daemon. To keep them, start with keepTree: true; they run until kill on that task, which keeps the root's result, or the end of the tasks' owner (the session in the default mode, the daemon with FASTEXEC_DAEMON=on), and killAfterMs bounds them too. Once a result has shown bash's exit, polls wait on such a task as on a running one, until its processes end, and returnWhen waits past a bash exit 0 for their output. A server can also run in the foreground as its own task. On Windows, `explorer.exe <app.exe>` hands a GUI app to the desktop for good.
- list: every task this server holds, with its bare task ID, owner and, for a call through the daemon endpoint, the session and call ID that started it. Server instructions state how long tasks live.
- transcript: a PTY task's output as a terminal shows it, each line pushed off the screen once, with each alternate-screen session merged from the frames it showed where it ran; for reading a long conversation inside a TUI. Returns the lines since the last transcript call, then the pending lines still on screen, which may change; the file in the status line holds the whole text, for grep and sed -n. Text the program never showed on screen is absent.

Reader handles: a start result's taskId is your own reader handle (`<taskId>.<reader>`); poll with it for unseen output. IDs from list and the background footer are bare: polling one creates a new reader from the start of the retained log, returns its handle, and says `new reader` on its first delivered output, transcript, or screen result. An evicted reader or a handle used in a new session attaches again. Keep the returned handle for subsequent calls. HTTP clients sharing a token share background notices; the footer counts other clients' running tasks. Log retention and truncation still apply.

Output: stdout and stderr form one stream. ANSI codes are stripped and progress-bar rewrites collapse to their final text (raw: true keeps them). Results fit maxBytes (100-1048576, default 16384) with truncate head_tail (default), head, or tail, which also cut lines over 2000 chars (64 KiB with raw) and count them in cutLines; none returns unseen lines whole up to 4 MiB and reports the rest as an omitted range. Errors and correctness warnings stay whole, even beyond maxBytes. Warnings distinguish permanent output loss from display truncation. Narrow output in the command (cmd 2>&1 | grep ... | tail -n 50, with set -o pipefail). The log file in the status line keeps up to 64 MiB; read omitted lines with sed -n 'A,Bp' or grep.

stdin: a poll waits for the writer to acknowledge its input; a failed write or unconfirmed delivery is an error. An unconfirmed write may be partially delivered or still queued: do not blindly retry. In pipe mode stdin stays open until eof or exit, so programs reading stdin wait; pass eof: true or use < /dev/null. Canonical PTY input carries a warning because the terminal can discard long lines even across polls; use a pipe or file for long text.

PTY (pty: true): for programs that need a terminal, including password prompts such as ssh. Type text with input and press keys with keys, named as in tmux send-keys: "Enter", "C-c", "C-d", "Up", "Escape". Use keys, not input, for Enter and control keys: a newline in input is not Enter to a TUI. For full-screen and TUI programs (vim, top, less), pass screen: true to see the rendered screen instead of every redraw. Input, passwords included, is recorded in the transcript. Keys go out keyDelayMs (default 150) apart, the first one after input, so a TUI that detects pastes by timing (Codex) takes Enter as a key press; raise it above a program's escape timeout when Escape precedes another key.

PTY size: cols 20-500 and rows 5-200; start defaults 120x30, and a poll changes the size with cols and/or rows, keeping the value of an axis it omits. A resize takes effect before the poll's input and keys, and the program sees it: SIGWINCH on Unix, a repaint of the whole screen from ConPTY on Windows. An unchanged size does nothing. A width change reflows wrapped rows, which changes their text. A resize never loses transcript text on either screen: the screen as it stands is written out at the old size, and rows still visible after the resize may appear a second time. Arbitrary application redraws keep today's best effort. A resize after the task's tree ended, or a size on a pipe task, is refused.

returnWhen: the first condition that holds ends the wait, and waitEndedBy names it with the matched text. outputContains suits plain output, such as a server's ready line. A TUI redraws old text, so watch its screen: screenAppears for a line it adds when done (Codex: "Worked for") and screenGone for a busy indicator (pi: "Working"), both compared with the screen before this call's input, or screenContains for a state that may already show. Add quietMs (about 3000) as a fallback: TUIs animate while busy and go quiet when idle. Send the prompt and Enter in the poll that waits.

U+FFFD in output means another encoding: pass encoding ("big5", "gbk").
