Run bash commands as tasks: Git Bash on Windows, system bash elsewhere. Write POSIX bash.
- start: runs `command` in a fresh bash and waits up to waitMs (default 30000). If it exits in time you get the final result; otherwise a taskId and the output so far while it keeps running. A non-zero exit code is a normal result. Every start is a new shell: cd and exports do not carry over, so pass cwd (default: the server's working directory) or chain with &&.
- poll: writes `input` exactly as given, then presses `keys` (PTY only), closes stdin when eof is true, waits until the task ends, a returnWhen condition holds, or waitMs elapses (default 2000 with input or keys and no returnWhen, 30000 otherwise), and returns only output you have not seen. Use long waits (up to 240000) for builds and tests, and returnWhen for servers, prompts, and TUIs; avoid repeated waitMs 0 polls and sleep commands. The process keeps running past every wait.
- kill: ends the task's whole process tree; poll afterwards for remaining output. Programs a task starts, including with `&`, `nohup`, `start`, `cmd /c start`, or `Start-Process`, belong to its tree and end when its root bash exits. To keep one running, start it in the foreground as its own task, which runs until kill or session end, or hand it to a launcher outside the tree: on Windows `explorer.exe <app.exe>` for GUI apps; on Linux `setsid -f <command>`.
- list: this server's tasks. All tasks end when the session ends.
- transcript: a PTY task's whole output as a terminal shows it, scrollback history then screen, each line once, then each alternate-screen session merged from the frames it showed; for reading a long reply inside a TUI. Returns the last lines and writes the full text to the file in the status line. An alternate-screen session lacks text the program never showed on screen.

Output: stdout and stderr form one stream. ANSI codes are stripped and progress-bar rewrites collapse to their final text (raw: true keeps them). Results fit maxBytes (default 16384) with truncate head_tail (default), head, or tail, which also cut lines over 2000 chars (64 KiB with raw) and count them in cutLines; none returns every unseen line whole and leaves limits to the host. Narrow output in the command (cmd 2>&1 | grep ... | tail -n 50, with set -o pipefail). The log file in the status line keeps up to 64 MiB; read omitted lines with sed -n 'A,Bp' or grep.

stdin: in pipe mode stdin stays open until eof or exit, so programs reading stdin wait; pass eof: true or use < /dev/null.

PTY (pty: true): for programs that need a terminal, including password prompts such as ssh. Type text with input and press keys with keys, named as in tmux send-keys: "Enter", "C-c", "C-d", "Up", "Escape". Use keys, not input, for Enter and control keys: a newline in input is not Enter to a TUI. For full-screen and TUI programs (vim, top, less), pass screen: true to see the rendered screen instead of every redraw. Input, passwords included, is recorded in the transcript. Keys go out keyDelayMs (default 150) apart, the first one after input, so a TUI that detects pastes by timing (Codex) takes Enter as a key press; raise it above a program's escape timeout when Escape precedes another key.

returnWhen: the first condition that holds ends the wait, and waitEndedBy names it with the matched text. outputContains suits plain output, such as a server's ready line. A TUI redraws old text, so watch its screen: screenAppears for a line it adds when done (Codex: "Worked for") and screenGone for a busy indicator (pi: "Working"), both compared with the screen before this call's input, or screenContains for a state that may already show. Add quietMs (about 3000) as a fallback: TUIs animate while busy and go quiet when idle. Send the prompt and Enter in the poll that waits.

Windows: Git Bash rewrites arguments that look like POSIX paths (/c, /F, /tmp/x) for native programs; prefix MSYS_NO_PATHCONV=1 or set MSYS2_ARG_CONV_EXCL. Run PowerShell from a script file (pwsh -NoProfile -NonInteractive -File x.ps1) or with -EncodedCommand. loginShell: false skips the profile and starts faster.

U+FFFD in output means another encoding: pass encoding ("big5", "gbk").
