Run bash commands as tasks: Git Bash on Windows, system bash elsewhere. Write POSIX bash.
- start: runs `command` in a fresh bash and waits up to waitMs (default 30000). If it exits in time you get the final result; otherwise a taskId and the output so far while it keeps running. A non-zero exit code is a normal result. Every start is a new shell: cd and exports do not carry over, so pass cwd (relative paths resolve against the session's directory, ~ is home; default: the working directory the session started in) or chain with &&. input feeds stdin; see stdin below. NUL bytes in command are rejected before execution.
- poll: resizes the terminal (PTY only) with cols and/or rows, then writes `input` exactly as given, then presses `keys` (PTY only), closes stdin when eof is true, waits until the task ends, a returnWhen condition holds, or waitMs elapses (default 2000 with a resize, input, or keys and no returnWhen, 30000 otherwise), and returns unseen output. Use long waits (up to 240000, within a 5-minute prompt-cache lifetime; poll again for longer) for builds and tests, and returnWhen for servers, prompts, and TUIs; avoid repeated waitMs 0 polls and sleep commands. The process keeps running past every wait.
- kill: ends the task's whole process tree, waiting up to 5 s to confirm (waitMs is ignored), and returns the output you have not seen. Processes a command leaves running belong to its tree, end when root bash exits, and are named in the result: `&`, `nohup`, `setsid`, `start`, `Start-Process`, or CLI background servers (adb, Gradle daemon). To keep them, start with keepTree: true; they run until kill on that task (keeping bash's result), killAfterMs, or the end of the tasks' owner (this session, or the daemon with FASTEXEC_DAEMON=on). Once bash's exit is shown, polls wait until kept processes end, and returnWhen waits past exit 0 for their output. A server can also run in the foreground as its own task. On Windows, `explorer.exe <app.exe>` hands a GUI app to the desktop for good.
- list: this session's tasks, newest first (scope "all" for every task; state "active" or "finished"; limit, default 20), with bare task ID, owner and, for a call through the daemon endpoint, the session and call ID that started it. Server instructions state how long tasks live.
- transcript: a PTY task's output as a terminal shows it, each scrolled-off line once, with alternate-screen sessions merged where they ran; for reading a long TUI conversation. Returns lines since the last transcript call, then pending on-screen lines; the status line's file holds the full text for grep and sed -n. Unshown text is absent.

Reader handles: a start result's taskId is your own reader handle (`<taskId>.<reader>`); poll or kill with it for unseen output. IDs from list and the background footer are bare: polling or killing one creates a new reader from the start of the retained log, returns its handle, and says `new reader` on its first delivered output, transcript, or screen result. An evicted reader or a handle used in a new session attaches again. Keep the returned handle for subsequent calls. Log retention and truncation still apply. HTTP clients sharing a token share background notices. A session's first result also counts tasks running outside it, such as an earlier session's; list them with scope "all".

Output: stdout and stderr form one stream. ANSI codes are stripped and progress-bar rewrites collapse to their final text (raw: true keeps them). Results fit maxBytes (100-1048576, default 16384) with truncate head_tail (default), head, or tail, which also cut lines over 2000 chars (64 KiB with raw) and count them in cutLines; none returns unseen lines whole up to 4 MiB and reports the rest as an omitted range. Errors and correctness warnings stay whole, even beyond maxBytes. Warnings distinguish permanent output loss from display truncation. Narrow output in the command (cmd 2>&1 | grep ... | tail -n 50, with set -o pipefail). The log file, named in the status line when output was omitted or cut or the task is still running, keeps up to 64 MiB; read omitted lines with sed -n 'A,Bp' or grep.

stdin: a pipe task started without input reads an empty stdin (/dev/null, NUL on Windows), so a command that reads stdin gets end of file at once instead of waiting: a prompt fails or exits, and rg searches the working directory. Give answers as start's input (up to 1 MiB), after which stdin closes, or start with eof: false to keep stdin open for poll input; a poll with eof: true closes it. A poll waits for the writer to acknowledge its input; a failed write or unconfirmed delivery is an error. An unconfirmed write may be partially delivered or still queued: do not blindly retry. PTY tasks read their terminal: start takes no input, and polls type with input and keys. Canonical PTY input carries a warning because the terminal can discard long lines even across polls; use a pipe or file for long text.

PTY (pty: true): for programs that need a terminal, including password prompts such as ssh. Type text with input and press keys with keys, named as in tmux send-keys: "Enter", "C-c", "C-d", "Up", "Escape". Use keys, not input, for Enter and control keys: a newline in input is not Enter to a TUI. For full-screen/TUI programs (vim, top, less), pass screen: true for the rendered screen instead of every redraw. Input, passwords included, is recorded in the transcript. Keys go out keyDelayMs (default 150) apart, including the first after input, so timing-based paste detection (Codex) takes Enter as a key press; raise it above a program's escape timeout when Escape precedes another key.

PTY size: cols 20-500 and rows 5-200, default 120x30; a poll resizes with cols and/or rows before its input and keys, and a width change reflows wrapped rows.

returnWhen: the first condition that holds ends the wait, and waitEndedBy names it with the matched text. outputContains suits plain output (e.g. a server ready line). A TUI redraws old text, so watch its screen: screenAppears for a line it adds when done (Codex: "Worked for") and screenGone for a busy indicator (pi: "Working"), both compared with the screen before this call's input, or screenContains for a state that may already show. Add quietMs (about 3000) as a fallback: TUIs animate while busy and go quiet when idle. Send the prompt and Enter in the poll that waits.

U+FFFD in output means another encoding: pass encoding ("big5", "gbk").
