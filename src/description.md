Run bash commands as tasks: Git Bash on Windows, system bash elsewhere. Write POSIX bash.
- start: runs `command` in a fresh bash with this session's login-environment snapshot (pass loginShell: true to run login profiles) and waits up to waitMs (default 30000). If it exits in time you get the final result; otherwise a taskId and output so far while it keeps running. A non-zero exit code is normal. Every start is a new shell: cd and exports do not carry over, so pass cwd (relative to the session directory, ~ is home; default: the directory the session started in) or chain with &&. input feeds stdin; see stdin below. NUL bytes in command are rejected before execution.
- poll: resizes the terminal (PTY only) with cols and/or rows, writes `input` as given, presses `keys` (PTY only), closes stdin when eof is true, waits until the task ends, returnWhen holds, or waitMs elapses (default 2000 with resize, input, or keys and no returnWhen, 30000 otherwise), and returns unseen output. Use long waits (up to 240000, within a 5-minute prompt-cache lifetime; poll again for longer) for builds and tests, and returnWhen for servers, prompts, and TUIs; avoid waitMs 0 loops and sleep commands. The process keeps running past every wait.
- kill: ends the task's process tree, waiting up to 5 s to confirm (waitMs is ignored), and returns unseen output. Leftover processes end when root bash exits and are named in the result: `&`, `nohup`, `setsid`, `start`, `Start-Process`, or CLI daemons (adb, Gradle). Start with keepTree: true to keep them until kill (preserving bash's result), killAfterMs, or owner shutdown (this session, or the daemon with FASTEXEC_DAEMON=on). Once bash's exit is shown, polls wait until kept processes end, and returnWhen waits past exit 0 for their output. On Windows, `explorer.exe <app.exe>` hands a GUI app to the desktop.
- list: this session's tasks, newest first (scope "all" for every task; state "active" or "finished"; limit, default 20), with bare task ID, owner and, through the daemon endpoint, the session and call ID that started it. Server instructions state task lifetime.
- transcript: a PTY task's output as a terminal shows it, each scrolled-off line once, with alternate-screen sessions merged where they ran; for reading a long TUI conversation. Returns lines since the last transcript call, then pending on-screen lines (waitMs is ignored); the status line's file holds the full text for grep and sed -n. Unshown text is absent.

Reader handles: a start result's taskId is your reader handle (`<taskId>.<reader>`); poll or kill with it for unseen output. IDs from list and the background footer are bare: polling or killing one attaches a new reader from the retained log's start, returns its handle, and says `new reader` on its first delivered output, transcript, or screen result. Evicted or cross-session handles reattach. Keep the returned handle. Log retention and truncation apply. HTTP clients sharing a token share background notices. A session's first result also counts outside running tasks; list them with scope "all".

Output: stdout and stderr form one stream. ANSI codes are stripped and progress-bar rewrites collapse to their final text (raw: true keeps them). Body text fits maxBytes (100-4194304, default 16384; status, footer, errors, and warnings stay outside it) with truncate head_tail (default; tail for transcript), head, or tail. Lines have no fixed length cap; an overflowing single line cuts at a UTF-8 boundary and increments cutLines. Warnings distinguish permanent output loss from display truncation. Narrow output in the command (cmd 2>&1 | grep ... | tail -n 50, with set -o pipefail). The log file (up to 64 MiB), named when output was omitted or cut or the task runs, holds omitted lines for sed -n 'A,Bp' or grep.

stdin: a pipe task without input reads empty stdin (/dev/null, NUL on Windows), getting EOF at once instead of blocking: prompts fail and rg searches cwd. Pass start's input (up to 1 MiB, closing stdin unless eof: false), or eof: false to stream poll input; poll eof: true closes it. Polls wait for write acknowledgement; failed or unconfirmed writes error and may have partially arrived, so do not blindly retry. PTY tasks read their terminal: start takes no input, and polls type with input and keys. Canonical PTY input warns that long lines can be discarded across polls; use a pipe or file for long text.

PTY (pty: true): for programs needing a terminal, including ssh password prompts. Type text with input and press keys with keys (tmux send-keys names: "Enter", "C-c", "C-d", "Up", "Escape"). Use keys, not input, for Enter and control keys. Pass screen: true for full-screen TUIs (vim, top, less). Transcripts record echoed input, including passwords. Keys go out keyDelayMs (default 150) apart, including the first after input, so paste detection (Codex) treats Enter as a key press; exceed a program's escape timeout when Escape precedes another key.

PTY size: cols 20-500 and rows 5-200, default 120x30; a poll resizes before input and keys, reflowing wrapped rows on width changes.

returnWhen: the first matching condition ends the wait, reported in waitEndedBy. outputContains suits plain output (e.g. a server ready line). For TUIs that redraw old text, watch the screen: screenAppears for a new completion line (Codex: "Worked for"), screenGone for a busy indicator (pi: "Working"), both compared against the screen before input, or screenContains for a state already shown. Add quietMs (~3000) as a fallback when animations stop. Send prompt and Enter in the waiting poll.

U+FFFD in output means another encoding: pass encoding ("big5", "gbk").
